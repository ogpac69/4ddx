# D4.1–D4.2 UI integration

## Registry
The existing 11-module, 178-question questionnaire remains the authoring source in this release. At startup, `D4QuestionnaireRegistry.build(modules)` creates and validates a canonical registry. Field rendering now resolves each question by stable ID from that registry; labels, input types, options, placeholders, domains and units come from the registry definition. Numeric values receive finite-number validation while blank optional answers remain allowed.

## Longitudinal view
The Trends view now calls `D4Longitudinal.collect(db)` and summarizes supported metrics from existing `logs` and `healthData.daily`. Temperature is normalized to Celsius for analysis while raw Fahrenheit readings remain untouched in storage. The panel displays record count, latest, mean, median, range and latest date. It does not infer missing values, smooth data, or assign diagnoses.

## Safety and compatibility
No data migration or writes are performed by the new engine. The existing DB key and JSON export format remain unchanged. The new panel is read-only.

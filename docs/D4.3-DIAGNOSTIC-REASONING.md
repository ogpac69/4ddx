# D4.3 — Transparent diagnostic reasoning engine

## Purpose
D4.3 adds a data model for documenting competing explanations without pretending to diagnose. It records a clinical question, observations, a timeline, and multiple hypotheses. Each hypothesis has an explicit interpretive perspective, evidence label, supporting and contradicting observations, confounders, predictions, falsifiers, missing data, and source notes.

## Evidence labels
- `established_mechanism`: a well-established physiological mechanism; this does not establish that it explains the case.
- `supported_hypothesis`: an interpretation with some supporting evidence; still provisional.
- `contested_claim`: an interpretation with materially disputed evidence or acceptance.
- `speculation`: a plausible but weakly substantiated interpretation.
- `unknown`: not assessed or not adequately characterized.

The engine does not verify evidence labels. They must be justified in source notes and reviewed independently.

## Perspectives
- `mainstream_clinical`: conventional clinical interpretation.
- `bioenergetic_peat_ling`: Ray Peat / Gilbert Ling-inspired interpretation.
- `other`: another explicitly identified perspective.

These perspectives are stored separately, not blended into a single evidence score. Bioenergetic framing is a lens for generating questions, not proof of a mechanism or diagnosis.

## API
`createCase(input)` creates a new case.
`addHypothesis(caseData, hypothesis)` returns a copied case with a new hypothesis.
`updateHypothesis(caseData, id, patch)` returns a copied case with one hypothesis updated.
`assessCompleteness(hypothesis)` reports which reasoning fields are populated. Its percentage is documentation completeness only, never diagnostic confidence.
`review(caseData)` produces a transparent review and limitations.
`validate(caseData)` checks schema and controlled values.

## Safety and limitations
The safety review stores red-flag observations entered by the user or clinician. Any entered red flag prompts human clinical review; the engine does not determine urgency or severity. An empty red-flag list does not establish safety. Suspected emergencies require local emergency services or urgent medical assessment.

No diagnosis, disease ranking, probability, causal inference, treatment recommendation, or medication/supplement dose is generated. Missing information is not treated as a negative finding. The module does not read or write localStorage and is not connected to participant data.

## Integration status
Engine and unit tests only. No app UI, profile schema, localStorage, import/export, or existing records are changed in D4.3. UI integration should follow only after the reasoning workflow and consent/privacy boundaries are reviewed.

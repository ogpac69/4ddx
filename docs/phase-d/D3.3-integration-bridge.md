# D3.3 — Feature-flagged assessment integration bridge

Status: integration bridge implemented and tested; not yet wired into `app/index.html`.

## Why this release is conservative
The live app reads and writes primitive values through `db.assessment[questionId]`. Replacing that object or switching reads globally could break questionnaire rendering, completion calculations, reports, and historical analytics. D3.3 therefore introduces a bridge without changing the live app.

## New module
`engine/d3-assessment-bridge.js` depends on `engine/d3-assessment-data.js`.

Functions:
- `preview(profile)` — pure migration preview; returns before/after counts, validation, and a migrated copy.
- `migrateWithBackup(profile)` — returns a complete JSON backup and migrated copy. It does not persist either.
- `rollbackFromBackup(json)` — restores the exact profile object from a valid pre-migration backup.
- `isEnabled(storage)` / `setEnabled(storage, bool)` — fail-closed feature flag.
- `read(profile, id, enabled)` — uses legacy values while disabled; uses structured values first when enabled.
- `summarize(profile)` — counts legacy and structured keys.

## Required activation sequence
1. Keep the feature flag off.
2. Ask the user to export a full JSON backup using the existing app backup function.
3. Run preview and show the user counts and validation result.
4. Save a separate pre-migration backup file and verify that it can be reopened.
5. Persist the returned migrated profile only after explicit confirmation.
6. Keep the legacy `assessment` object unchanged.
7. Enable structured reads only after analytics parity tests pass.
8. If parity fails, turn the feature flag off and restore the pre-migration backup.

## What is not done
- No changes to `app/index.html`.
- No automatic migration on page load.
- No automatic localStorage writes.
- No change to completion score, charts, report, questionnaire rendering, or supplement data.
- No clinical interpretation or diagnosis.

## Next integration gate
D3.4 should wire the bridge into the app's backup/settings flow, add an explicit "Preview migration" and "Migrate after backup" control, then compare old and new analytics outputs on identical synthetic and user-approved backup copies.

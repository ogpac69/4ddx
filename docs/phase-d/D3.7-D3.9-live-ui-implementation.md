# D3.7–D3.9 live UI implementation

The Settings rollout card exposes three operations: a local parity check, an explicit structured-read enable action, and a legacy-read fallback. It also exposes the D3.6 shadow-write flag.

The parity check is synchronous and local. It compares the active `modules` question IDs, normalizing blank legacy values to `not_answered`. A missing structured answer for a nonblank legacy answer is a mismatch. It reports IDs and statuses, not answer contents.

Structured reads are gated by both `D3AssessmentData.validateProfile` and parity. The feature flag is `d3_assessment_v2_read_enabled`; it is off by default. The shadow-write flag is `d3_assessment_v2_shadow_write_enabled`; it is independently controlled and off by default.

On questionnaire save, legacy fields are updated first. If shadow writes or structured reads are enabled, `D3AssessmentIntegration.sync` refreshes the structured copy before `saveDB()`. A sync error stops persistence and is displayed in the rollout status area.

The selected read view is used for questionnaire values and completion indicators. Daily log measurement views are not changed. Migration and rollback explicitly turn off structured reads and shadow writes.

No automatic migration, remote telemetry, or server-side profile storage is introduced.

# D3.5 — Questionnaire source synchronization

Status: source-derived registry generator and audit tests.

## Source of truth
The current rendered questionnaire is the `const modules = [...]` literal in the deployed `index.html`. D3.5 extracts the exact module titles, IDs, labels, control types, placeholders, and select options from that literal. It does not invent recall windows or clinical meaning.

## Outputs
Run `node scripts/sync-assessment-registry.js` from the repository root. This writes `schemas/assessment-question-registry.v2.json` with:
- exact source labels and control types;
- exact option values/labels for select controls;
- module and display order;
- response kind and conservative unit hints;
- sensitivity flags for review, not clinical classification;
- a SHA-256 fingerprint of the source HTML.

The 12 IDs carried from the earlier registry but not found in the rendered source are marked `legacy_only_not_rendered`. They are preserved for old profile compatibility and are not represented as current UI questions.

## Important audit findings
The source currently uses free-text fields for several compound constructs, including diagnoses/family history/medications, food reactions, injuries, cardiovascular activity, and lifestyle context. D3.5 records these exactly; it does not split or rename them. A later questionnaire redesign must add new IDs and explicit migration rules rather than repurpose existing IDs.

The current app stores all questionnaire values as strings through `saveAssessment()`. D3.5 therefore does not coerce numeric-looking strings to numbers. Units and recall windows are incomplete in the source and are flagged conservatively.

## Compatibility
Existing IDs remain immutable. Unknown keys, retired IDs, and the legacy `assessment` object must survive every migration and export. Registry generation is read-only with respect to participant data.

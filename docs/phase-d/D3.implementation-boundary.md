# D3 — Implementation boundary

D3 is initially a pure read-only analysis module. It must receive a cloned or immutable snapshot of the local database and return a report object. It must not call `localStorage.setItem`, network APIs, or mutate global `db`.

Suggested module boundaries for a later implementation:

- `parseTrackerData(input)` — shape and type validation.
- `normalizeObservations(parsed)` — normalized analysis view; raw input retained.
- `summarizeObservations(normalized, window)` — descriptive statistics only.
- `assessDataQuality(normalized)` — completeness and comparability.
- `retrieveKnowledge(catalog, datasets, query)` — eligible record selection.
- `composeAssessment(summary, quality, records)` — output contract only.
- `validateAssessmentOutput(report)` — schema validation.

Keep these functions pure. UI code should only request a report and render it. Do not make the report a persistent health record in this phase.

No external API, LLM, cloud function, or analytics endpoint is allowed in D3.1. If an AI-assisted narrative is considered later, it requires a separate privacy/security review, explicit consent, data minimization, and source-grounding controls.

# D3.6 — Structured assessment shadow integration

Status: opt-in structured shadow writes; legacy remains authoritative.

## Runtime module
`engine/d3-assessment-integration.js` depends on `D3AssessmentData` and `D3AssessmentBridge`.

`sync(profile, modules)` creates a migrated copy and refreshes structured answers for the currently rendered questionnaire IDs. It preserves raw legacy strings, including numeric-looking strings, and marks blank strings `not_answered`. It validates the complete profile before returning it. It never writes storage itself.

## UI patch
Run `node scripts/apply-d3.6-ui-integration.js` from the repository root. The script safely patches both `index.html` and `app/index.html`. It aborts if expected source anchors are missing rather than making a partial guess.

The Settings page receives an opt-in toggle named “Enable structured shadow writes”. When enabled, each questionnaire save updates `assessmentV2.answers`. The existing `assessment` object remains unchanged and continues to drive the questionnaire, completion score, dashboard, trends, and reports.

## Safety properties
- Off by default.
- No automatic migration on page load.
- No structured reads are enabled.
- No change to existing analytics or interpretation.
- No change to logs, health data, supplements, schedules, or adherence.
- No coercion of strings to numbers.
- No overwrite of unknown legacy keys.
- A failed shadow write does not intentionally discard the original in-memory legacy answers; the save routine reports the error and continues to persist legacy data.

## Cutover gate
D3.6 does not switch the application to structured reads. That requires a separate release with explicit parity tests for completion counts, dashboard summaries, trends, CSV/JSON exports, report output, and import/rollback behavior. The feature flag `d3_assessment_v2_enabled` remains distinct from the shadow-write toggle.

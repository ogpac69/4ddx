# 4DDX D4.1 + D4.2 — additive data foundation

Release version: D4.1 / D4.2

## D4.1 — Canonical questionnaire registry

`engine/d4-questionnaire-registry.js` builds a canonical registry from the app's existing `modules` array. This is intentional: the live questionnaire remains the source of truth for wording, question IDs, field types and select options. The registry adds domain IDs, order, unit hints, value types, missingness vocabulary, provenance vocabulary and basic validation metadata.

API:

- `D4QuestionnaireRegistry.build(modules)`
- `D4QuestionnaireRegistry.validateRegistry(registry)`
- `D4QuestionnaireRegistry.get(registry, questionId)`
- `D4QuestionnaireRegistry.byDomain(registry, domainId)`

The current live questionnaire was inspected during this release: 11 modules and 166 question items. The registry is generated at runtime from those exact definitions rather than maintaining a second, manually duplicated list. Unit hints are metadata, not conversions or proof that a value was measured correctly. Numeric bounds remain unset unless the product defines defensible limits.

## D4.2 — Longitudinal data engine

`engine/d4-longitudinal.js` is a pure, read-only transformation layer. It collects dated events from the existing `db.logs` and `db.healthData.daily` structures. It does not mutate the profile or write to localStorage.

Supported metrics include temperature, pulse, weight, height, waist, hip, sleep duration, sleep quality, steps, water, energy intake, protein, carbohydrate, fat and fiber. Known unit conversions include °F to °C, lb to kg, m/in to cm, mL to L and minutes to hours. Every normalized event retains `rawValue` and `rawUnit`, plus date/time, method, provenance, context, source and notes. Missing values are not filled or interpolated.

API:

- `D4Longitudinal.collect(profile)`
- `D4Longitudinal.event(input)`
- `D4Longitudinal.series(events, metric)`
- `D4Longitudinal.summarize(events, metric)`
- `D4Longitudinal.weekly(events, metric)`
- `D4Longitudinal.snapshot(profile)`

Summaries report count, first/last date, latest, minimum, maximum, mean, median and an optional descriptive least-squares slope when at least three dated numeric observations exist. These are descriptive statistics, not clinical reference ranges, causal estimates, forecasts or diagnostic scores. Repeated readings on the same date remain separate events; no silent averaging or deduplication occurs.

## Safety and compatibility

- Existing localStorage key and object shape are unchanged.
- No data migration, deletion, remote transmission, diagnosis or treatment recommendation is performed.
- Static questionnaire answers without a reliable observation date are not fabricated into time-series events.
- Original measurement values and units are retained beside normalized values.
- The engine is additive and currently not wired into visible app screens. UI integration is the next implementation step; installing these files alone does not add new charts or dashboard panels.
- Do not remove D3 legacy fields or archives as part of this release.

## Android installation

Extract the ZIP into the repository root, preserving paths. It adds `engine/d4-questionnaire-registry.js`, `engine/d4-longitudinal.js`, tests and this document. Commit and push through Gitling. No Node or terminal steps are required on the phone.

For the later UI integration, load both scripts after the existing D3 assessment scripts and before the main inline app script. Then initialize the registry with `D4QuestionnaireRegistry.build(modules)` and derive longitudinal views with `D4Longitudinal.collect(db)`. Do not replace existing save/import/export code in this phase.
